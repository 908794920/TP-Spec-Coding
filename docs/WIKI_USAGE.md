# Wiki 检索、读取与使用分析

Wiki 是已维护的源码理解与导航，不替代当前源码事实。需要查找时使用统一检索；已经知道文档时直接读取。不要求每项任务都搜索，也不为统计次数重复查询。

小修改、已知代码位置或当前上下文已经足够时，可以不使用 Wiki；陌生模块、跨模块关系或需要大范围定位时再按需查询。同一任务已取得的内容优先复用，不因切换角色或阶段重复读取。任务和角色已知时随调用传入，未知时保持未关联，不为遥测另建 Task。实际采用随已有 checkpoint/review/verify 记录，不增加专门的模型汇报。

## AI 使用入口

在已注册工作区执行（也可显式指定 `--workspace-root`）：

```powershell
tp-spec wiki index build --workspace-root <工作区>
tp-spec wiki search --workspace-root <工作区> --query "需要查找的术语" --task TASK-ID --role tp-development-engineer
tp-spec wiki read --workspace-root <工作区> --document-id "wiki:项目ID/仓库ID/相对文档路径" --task TASK-ID --role tp-development-engineer
tp-spec wiki read --workspace-root <工作区> --document-id "wiki:项目ID/仓库ID/相对文档路径" --start-line 81 --end-line 120
tp-spec wiki read --workspace-root <工作区> --document-id "wiki:项目ID/仓库ID/相对文档路径" --full
```

搜索默认只在当前 Wiki 项目中进行；跨项目须显式选择全局范围。结果包含稳定文档 ID、匹配片段、版本及回执。已知文档直接读取不必先搜索。索引构建与更新是显式维护操作，页面不会创建索引；成功完成的 Wiki 维护接续更新索引。缺失、过期或无法读取时保留真实状态。

CLI 搜索默认 5 条候选，每条摘要最多 200 个字符；确有需要时显式 `--limit` 扩大到最多 20 条。索引详细诊断使用 `wiki index status`，不自动扩大检索范围或翻页。

CLI 默认读取目录和短正文：目录最多 20 个标题且合计 1,000 个字符，正文最多 80 行且不超过 4,000 个字符，按完整原文行截取。`read_mode`、`truncated`、`next_start_line` 指示当前模式和续读起点；目录的 `line` 为原文行号，`outline_truncated` 表示目录是否完整。frontmatter 和代码围栏中的伪标题不作为目录。首正文行超出预算时只返回目录与显式按行读取建议，不跳过该行，也不计正文读取。

已有显式行范围按请求返回，`--full` 显式返回全文，两者互斥；是否扩大由当前需求决定。这些是字符预算，不是精确 token 估算。页面仍可阅读全文，不受 CLI 默认预览限制。索引不可用或过期时说明限制并按任务需要回到源码，不为计数重建索引或机械重试。

检索和读取可以携带 Task/角色用于归因，不传则显示未关联。一次逻辑调用重试时复用 `--request-id`；新的主动查询使用新回执。同一个回执不能代表不同输入。测试、诊断使用 `--no-telemetry`，避免污染真实使用。

`--document-id` 直接使用检索或 `wiki inventory` 返回的完整 ID，不按文件夹名称或 Runtime 项目 ID 猜测拼接。

## 采用不是命中

正式采用沿用 Task 的 `context_usage`，`source_type=wiki`、`asset_id` 使用返回的稳定 Wiki ID、`stage=adopted`，可带 `receipt_id` 关联检索或读取回执。只在实际采用时记录，证据引用遵守现有 portable 格式。搜索命中、读取文档或测试通过都不自动生成采用。

原有记录没有回执时保留原事实；仅对当前项目内唯一对应的旧文档 ID 建立关联，不猜测文档或历史搜索。任务采用数量按任务和文档去重；可信来源沿用既有 Context Effectiveness 规则。

## 本地数据与口径

- FTS5 索引和使用日志位于解析后的本机用户数据目录，按 Wiki 来源隔离。索引可重建，日志不因重建而清空。
- 搜索词和明细仅保存在本机，保留 90 天；明显凭据脱敏，清理只随 CLI 写入执行。脱敏是尽力识别，不应把秘密放进搜索词。
- 完成一次检索计一次搜索；返回多篇文档仍是一次。零结果计入分母，执行失败单列。没有样本时命中率为“—”。
- 返回正文或片段才计读取；搜索候选不计读取。无日志、查询失败和已采集范围内为零分别展示。
- 只有统一 CLI 的 AI 检索/读取能自动采集；普通 Shell/文件工具直接读 Wiki 无法被统计。缺少记录不等于没有价值。
- 人工页面浏览、筛选、搜索和刷新只读，不产生 AI 使用记录。页面读取现有 Runtime、索引、日志和维护工件，不初始化或迁移 Runtime。

## 工作台

侧栏 Wiki 是全局入口，知识库显示待开放。Wiki 默认最近 30 天，可选 7/30/90 天及项目。

“使用概况”显示搜索、命中、采用、按日趋势、项目使用、常用文档、维护摘要及待关注项。“文档”提供过滤、只读搜索和正文阅读。“检索记录”区分有结果、零命中和执行失败，并对照历史返回版本与当前版本。

检索日志与任务采用记录分别显示可用性。最近已记录搜索、正文读取、采用遵循当前项目和时间筛选；成功零命中属于搜索，失败执行不属于最近成功搜索。没有日志显示“尚未采集”，任务记录可读但没有 adopted 显示“当前范围未记录采用”；部分来源的时间仅代表已知范围，不解释为完整统计或 Wiki 从未被使用。

重复零命中、过期或反复读取但未记录采用仅是检查线索，不是自动修订、删除或判定无价值的依据。维护摘要显示既有报告及时间，不触发全仓检查。跨来源数据不承诺原子快照，部分项目不可读会标注缺失范围。
