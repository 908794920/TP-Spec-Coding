# 本地工作台：启动、数据接口与开发

## 当前能力与边界

侧栏提供全局 Wiki 与知识库入口。两者的使用概况、文档、检索记录与只读边界分别见 [Wiki 检索与使用分析](WIKI_USAGE.md) 和 [Knowledge 检索与使用分析](KNOWLEDGE_USAGE.md)。人工页面搜索和正文浏览不写 AI 使用记录；正式采集由相应 CLI 入口执行，页面没有索引维护或统计写入接口。

在 TP-Spec-Coding 自身源码根目录启动，不在每个业务仓库复制前端。提供全站总览、项目总览、任务工作区、全局配置、Wiki 和知识库页面，以及生命周期活动与执行计划步骤/角色参与、资料与 Work 抽屉、Task 四类详情、验收/证据适用性、按需结单预检、能力定义父子表、时间线和刷新异常处理。旧卡片专属链路已退出，只保留本地 Web 可视化入口和既有纯文本/JSON 查询。功能说明不代替验收；历史批次的通过、失败和未执行范围统一见 [CHANGELOG](../CHANGELOG.md)，现场检查按文末的当前场景选择。

页面只读现有注册表、Binding、Runtime 和工件。任务备注保存在对应 Task 目录下的 `.tp-spec/workbench-note.json`，随该任务目录归档。没有项目时显示真实空态，不插入演示数据；缺少数据库时返回缺失，不创建、修复或迁移。普通 CLI 运行不会启动工作台。

## Windows 轻量管理入口

依赖准备完成后，在 `ui` 目录双击 `start.cmd`、`restart.cmd` 或 `stop.cmd`，也可从任意当前目录调用；首次加载或依赖/锁文件变化后先双击 `install.cmd`。启动与重启成功后默认打开系统浏览器，后台运行前后端；重复启动复用当前受管实例。路径从脚本位置解析，不需要填写源码绝对路径。日志与本机实例记录保存在根 `workbench-logs/`，不进入发布清单。

管理器只停止通过这些入口启动的本目录实例，通过私有管道和实例令牌通知原启动器关闭两端，不按端口或进程名称杀服务。首次切换时，原 `npm run dev` 启动的前台实例需在原终端按 `Ctrl+C` 停止，再运行 `start.cmd`；端口冲突不会自动接管旧实例。并发管理操作会明确拒绝，异常中断留下的 `manager.lock` 需确认没有管理操作运行后再移除。

默认前端从 15173 开始；端口被占用或被系统拒绝监听时，依次尝试 15174、15175……，直到找到可用端口，最多到 65535。可在调用前设置 `TP_SPEC_WORKBENCH_PORT` 改变起始端口。浏览器、健康检查和实例记录使用实际端口；重复启动复用已运行实例，重启重新从起始端口选择。`start.cmd`/`restart.cmd`/`stop.cmd` 不安装依赖、不升级 Base、不运行测试；依赖准备只由 `install.cmd` 显式执行。启动失败查看 `workbench-logs/workbench.log`。

## 环境与启动

Python 沿用基座 3.10+ 及根 `requirements.txt`。前端 Node.js 范围为 `^20.19.0 || >=22.12.0`，精确依赖以根锁文件为准。

首次准备运行依赖（已有正确环境无需重复安装）：

```bash
python -m pip install -r requirements.txt
npm ci
npm run dev
```

Windows 上可用 `ui\install.cmd` 代替 `npm ci`：按 `package-lock.json` 安装，锁文件未变化时跳过重复安装（安装记录写在 `workbench-logs\install-state.json`，只记锁文件指纹与 Node/npm 版本），检测到受管工作台仍在运行时会拒绝安装。`install.cmd --python` 会一并执行上面的 `pip install`，`install.cmd --build` 会额外执行 `npm run build`，`install.cmd --force` 强制重装。

默认浏览器地址从 `http://127.0.0.1:15173` 开始选择；`--port` 指定另一前端起始端口，同样在占用或系统拒绝监听时递增。API 自动选择空闲的本机端口，显式 `--api-port` 的行为不变。实际地址、源码根和 API PID 会打印到终端。浏览器访问前端地址，由前端代理 `/api` 到本次 Python 实例。不要单独执行 Vite 后期待它自动找到任意已运行的 API。

```bash
npm run dev -- --port 15180
npm run dev -- --port 15180 --api-port 8765
npm run dev -- --help
```

原 `npm run dev` 前台入口不开放远程监听选项，不安装系统服务，不自动打开浏览器；上述 Windows 管理入口启动成功后会打开浏览器。退出使用 `Ctrl+C`；启动器只停止自己创建的进程，端口冲突时不会杀占用端口的其他服务。单端启动失败会关闭另一端并非零退出。

Python 选择顺序：`TP_SPEC_PYTHON` → 活动 `VIRTUAL_ENV` → 本项目 `.venv` → 系统 `python`（Windows）/`python3`（其他平台）。`TP_SPEC_PYTHON` 是解释器路径或可执行文件名，不是带参数的 shell 命令。路径通过参数数组传递，支持中文与空格；Windows 平台行为仍需在用户本机实际验证。

例如已在项目根创建 `.venv` 时，PowerShell 可显式指定：

```powershell
$env:TP_SPEC_PYTHON = (Join-Path $PWD '.venv/Scripts/python.exe')
npm run dev
```

启动器固定加载本目录的 `cli.workbench.server`，同时校验 Python readiness、实例身份与 `/api/health`。源码位置不是已配置安装位置时，不会自动替换安装配置。全局页面中的 `base` 是安装声明；`active_source_root` 与 health 的 `source_root` 才是本次执行源码；能力拓扑的内置部分使用本次源码，外部部分沿用同一进程的用户级根；不从安装声明中的另一份 Base 偷换正文来源。

## 数据选择与真实性

上下文键由正式 project id、注册项目根、选中工作区和实际 Runtime 路径共同生成。工作区来自 Registry 或现有 Workspace Inventory + Project Binding，不根据 Task 名称或磁盘扫描猜测归属。

Runtime/注册表位置沿用基座现有解析，包括已经支持的 `TP_SPEC_USER_ROOT`、`TP_SPEC_REGISTRY` 等变量。没有配置时工作台不代替用户执行 `project init`。页面每次进入对象或点击“重新读取”发起 GET，不轮询、不生成事件。跨上下文取消旧请求并清空旧显示；同上下文刷新失败保留旧内容与原读取时间，同时提示失败。

Task 首屏和实时路由各用一次 SQLite 只读事务，前端按 `read.task_revision` 合并两次读取。配置、任务工件和证据仍是文件系统实时读取，**不承诺 SQLite 与这些文件形成跨介质原子快照**。响应的 `read.consistency` 与 `read.note` 明确此边界。

首屏直接展示已登记的计划、角色活动和阻塞，可交互后才读取在途任务的 `/route`。工作台实时路由按需读取候选，每次请求使用一份现场快照，页面重进或手动刷新时重新读取。验证建议仍由正式的流程入口按需生成。请求结束即释放缓存，正式推进与结单继续使用现有 CLI 门禁。

Wiki 页面在一次读取中共用同来源的目录及其指纹来计算文档概况和索引状态，避免重复遍历所有已登记文档；下一请求仍重新检查文件。Wiki Registry 的解析仅在同次网页请求中按内容指纹复用，正式 CLI 保持原有读取方式。索引读取失败仍单独报告，不隐藏已读取的目录。

Wiki 首次目录读取可复用现有索引元信息中的清单解析缓存，使用前核对清单字节 SHA、缓存格式与元信息 SHA；文件状态、正文哈希及索引过期检测仍执行。缓存缺失、损坏或不适用时沿原 YAML reader 读取，页面不写缓存。准备方法与边界见 [Wiki 使用说明](WIKI_USAGE.md)。

任务基础快照的历史验证摘要仍标记 `current_applicability=not_evaluated`，不能仅凭其 PASS 判定当前通过。只有用户打开“历史与证据”抽屉中的非概况详情（阻塞 / 验证与验收 / 证据与交付）后，才另行读取证据/绑定与当前适用性；切换阶段、角色卡或浏览任务抽屉不触发这些检查。WorkItem 来自 `work_item`；Work Session 来自既有事件。采用新结果契约时，Work 的范围、尝试、结果和接收来自已登记事件；旧记录缺失字段保持未知。`data_support.agent_thread_binding` 仍明确未提供，不按 Wxx 名字推断宿主 Agent Thread。

字段敏感键处理复用旧展示策略，不另建账户、权限或数据脱敏框架。HTTP 接口不接受任意文件路径，不提供命令执行或 Runtime 写入动作。任务备注是独立的文件写入入口：仅接受本机工作台同源请求，保存时核对备注版本；版本冲突时拒绝覆盖，页面保留草稿供用户处理。

任务“阻塞”详情中的 `security_changes` 复用现有字段展开器，显示已登记安全变更的提案版本、行为单元、决定及当前适用性；未知/来源失效不标已批准。命令与来源校验边界见 [Security Change Authority](security-change-authority.md)。工作台不提供批准或实施操作；此处后端读取契约与真实浏览器验收分别核对。

父子表与未归属区均展示来源标识与状态，并复用同一正文阅读器，区分 Base 与外部包的相对路径，支持锚点、返回上一篇和显式人工检查停用内容。页面顶部“重新读取”刷新目录，详情内“重新读取正文”刷新当前文件；读取失败不把旧正文冒充当前内容。具体操作见 [外部能力页面阅读](EXTERNAL_SKILLS.md#页面阅读与来源跟踪)。实现说明不代表这些交互或真实宿主采用已经通过。

任务工作区中的 `WorkItem` 不改名为 Work Unit。Task 自身状态只读其正式记录，不根据所有工作项完成自动变绿；`current` 工作项标志不解释为执行者在线，也不据此猜测正在处理哪项工作。Task 基础响应事件时间线最多最近 50 条，并明确标注总数与截断提示；Verification/Review/Owner/Delivery 各自最多展示最近 20 条结果历史，均标明总数与返回数。

任务详情统一使用原生模态侧栏，800px 以下导航收为抽屉，520px 以下进一步收敛工具栏和字段布局。目标视口为 1440/1024/715/480 CSS px；历史检查范围见 [CHANGELOG](../CHANGELOG.md#history-task-mainline)，不能将其中一批结果外推为后续所有页面均已验证。详情和表格独立滚动，状态有文字，不只靠颜色；系统字体，无外部字体/CDN。

## 具体执行计划与角色参与

正式采用 `tp-spec.execution/v1` 的 Task，任务工作区按“当前进展与阻塞/等待 → 生命周期活动 / 执行计划横向步骤 → 角色工作卡 → 角色参与抽屉”展示，读取现有 `task_event` 里的版本化计划、步骤边界和独立角色参与，不在浏览器重建业务状态机。登记、等待/恢复、交接和兼容规则见 [执行事实契约](EXECUTION_FACTS.md)。未采用显式计划的旧任务在存在已登记阶段时展示生命周期活动或流程状态，缺计划时不退回或补造通用阶段与参与记录。

顶部高亮展示当前进展、阻塞/等待原因、解除条件和下一责任人；若任务或当前步骤等待关联 Work，直接提供 Work 按钮跳转到“资料与 Work”抽屉并展开对应条目。点击“生命周期活动”与“执行计划”（无计划且有旧阶段数据时为“流程状态”）可在已记录生命周期阶段与计划步骤间切换；“已完成 X / 共 Y 步”只表示步骤历史，不换算 Task 完成比例。当前缺失不拿下一步充当当前，步骤都结束也不自动完成 Task。

点击步骤在下方展示该步“角色工作与记录”卡片，并可展开查看本步目标、前置步骤与本步全部事件；点击角色卡片打开右侧抽屉，展示该角色最新主要参与范围、结果、等待原因、下一责任、发现/决定/证据引用和起止详情。尚无实际记录的计划角色保留明确提示，不编造时间。抽屉支持切换“本次参与”“本角色在本步骤的全部参与”“本步骤全部事件”，按正式事件 ID 倒序、每页 8 条，显示匹配数与本步骤总事件数。该集合使用完整 execution timeline/history，不受任务基础日志最近 50 条的限制；生命周期活动视图则展示按阶段聚合的已取得活动与角色事件（若被总事件上限截断会提示条数上限）。

终态或退休任务不显示当前/下一责任；未闭合参与标为“历史未结束”，不据此推断在线。耗时只展示有可信起止的记录跨度，包含等待，不是 CPU 时间或模型工时。损坏记录与门禁路由错误可见，读取失败继续沿用原失败/旧快照提示；点击与筛选不会写 Runtime 或代签 PASS。

右上角提供“资料与 Work”与“历史与证据”两个抽屉入口：前者展示任务文档及可展开的“子工作与集成候选”（点击 Work 按钮展开并聚焦对应项，收起该项返回原触发按钮）；后者提供直达 Task 四类详情的快捷按钮、读取状态、问题清单、Task 事件时间线与路由/边界只读诊断。该 UI 复用现有 Ant Design、统一样式和只读接口；前端类型检查、构建及真实浏览器验证与后端/静态检查分别记录，不从源码中的按钮或 CLI 通过推断实际交互通过。

## 详情、证据和结单解释

从“历史与证据”抽屉或阻塞/等待入口打开 Task 模态详情，提供“概况 / 阻塞 / 验证与验收 / 证据与交付”四类页签。概况使用当前 Task 快照；首次进入其他标签才请求 `/details`，之后可以手动重新读取。WorkItem 与集成候选详情在“资料与 Work”抽屉独立展开，验收、验证、交付和预检明确属于当前 Task，不借用替代单个 Work 的真实范围与证据。

| 信息 | 展示含义 |
|---|---|
| Task 正式状态 | 读取 Runtime；工作项都完成、Delivery READY 或预检 ready 不会改变它 |
| Verification | 原记录结论与当前适用性分列；复用当前验证读取、subject 与产品 ChangeSet 校验，保留 technical/full 范围 |
| Review | 复用现有可信 CODE Review 判定；不跳过新失败去续用旧 PASS，不将未细分错误猜成具体 stale 原因 |
| Owner | 原始 accept/defer/waive、有效 AC、视觉 AC、来源和绑定分别展示；不扩大实际人验覆盖范围 |
| 验收矩阵 | 来自 acceptance.md 的声明、见证、方法和证据；文件写 PASS 不等于可信验收通过 |
| 证据引用 | 每次引用保留事件、字段与原哈希；可定位的任务内文件核对实际字节，旧裸路径不猜锚点；哈希相等不证明内容或验收结论 |
| Delivery | 当前匹配与历史 READY 分开；没有单独“用户接收交付”事实时不从 Owner 验收或 READY 推断 |

在“阻塞”标签中点击“读取结单预检”才调用现有 `record_first.completion_check()`。页面完整保留其实际返回的 blockers、acceptance_issues、route，不自行计算门禁，不运行 Verify/Review/Complete。没有返回责任方或恢复条件时显示未记录；路由责任方不能套给所有问题。`checks` 同时呈现各已登记门禁的适用性、责任和依赖，`unknowns` 不算通过；该检查不能证明未登记业务要求、现场操作或未执行的真实验收。

### 逐项结单预检

结单面板按需读取与 CLI/正式 Complete 相同的 `completion_check`，展开每项可查看依据、适用性、缺口、责任和依赖；未知项使响应标为部分结果，不被计作成功。刷新中、刷新失败或账本观察版本不同会把保留内容标为历史预检，停止展示当前“允许 Complete”。已终态显示原状态，不把取消当作完成，不由最后角色推导当前执行者。工作台不执行修复、批准、知识写入或结单；文件跨介质一致性限制随读取响应展示。

读取时间分别对应任务快照、详情、预检。`read.task_revision` 仅是 Task 行与最新事件 ID 的账本观察摘要，不是产品/证据文件的原子版本。标识不同时页面提示不能拼为同次快照；即使相同，也不承诺文件系统原子性。读取中已发现验收声明变化/消失时，返回部分结果，并撤回“当前适用”的展示结论，提示重新读取，不修改账本。

页面上的“重新读取”会更新已打开的数据；从未请求的详情/预检不会为了刷新后台预先运行。读取失败保留原内容、原读取时间和失败提示。接口返回其他上下文/Task、过时请求或不匹配展示契约时不会覆盖当前页面。跨 Task 清除旧选择与详情；同 Task 刷新不重置展开状态或抢焦点。实际生命周期、焦点和响应式行为按当前受影响页面验证，既有局部记录不代替未覆盖场景。

## API 与备注写入边界

| GET 路径 | 数据 |
|---|---|
| `/api/health` | 本次源码、版本、Python、Registry 路径及实例身份；不代表所有项目都可读 |
| `/api/global` | 全局配置、能力目录、注册项目/工作区上下文及读取问题 |
| `/api/skill-documents/{id}` | 精确 ID 的入口正文；`path` 相对 Base 发布目录或所属外部包；`allow_disabled=1` 仅用于显式人工检查停用内容，不接受任意本机文件 |
| `/api/wiki/{operation}` | `operation` 为 `overview`、`documents`、`document`、`search` 或 `records`，见 [Wiki 使用说明](WIKI_USAGE.md) |
| `/api/knowledge/{operation}` | `operation` 为 `overview`、`documents`、`document` 或 `records`，见 [Knowledge 使用说明](KNOWLEDGE_USAGE.md) |
| `/api/projects/{context_key}` | 指定上下文项目概况及完整 `task_index` |
| `/api/projects/{context_key}/tasks/{task_id}` | 正式任务、WorkItem、Work Session、现有流程和基础证据投影 |
| `/api/projects/{context_key}/tasks/{task_id}/route` | 按需读取在途任务的当前流转路由，按 `read.task_revision` 与任务快照对齐 |
| `/api/projects/{context_key}/tasks/{task_id}/details` | 按需读取验收声明、可信结果、适用性、等待及证据文件核对 |
| `/api/projects/{context_key}/tasks/{task_id}/closeout` | 显式调用既有 `completion_check()`；不运行 verify 或 complete |

项目、任务、全局配置及 Wiki/Knowledge 的成功结果为 `{schema, context, read, data}`；`health` 返回实例身份，能力正文保留 `{schema, id, path, content}` 并追加 `source_kind/source_root/status/enabled/entry_path/content_sha256` 等来源字段，具体见 [外部 SKILL](EXTERNAL_SKILLS.md#工作台后端与正文接口)；不要将后两者按标准 envelope 解析。schema 为 `tp-spec.workbench/v1`，不是 Runtime schema 升级。错误为 `{schema, error:{code,message}, failed_at}`，读取失败不附伪成功时间。非法参数/不支持的文档路径 400，缺对象 404；上下文/工件冲突 409；能力正文超限 413；不可读按具体来源返回 404、503 或 500；非 GET 动作返回 405。响应 `Cache-Control: no-store`。

`/details` 与 `/closeout` 使用各自请求内只读事务，并沿用既有 Runtime 判断。没有用户显式请求时，不执行结单预检。

## 开发、构建与 Git

```bash
npm run dev
npm run check:types
npm run build
```

三者相互独立，不串联测试。`build` 仅生成 `ui/workbench/dist/`，不是生产部署，也不等于 `file://` 可用；本版默认使用本地工作台启动入口。没有安装依赖时先 `npm ci`（Windows 可直接 `ui\install.cmd`），不应为了通过命令临时换依赖版本。

修改页面见 `ui/workbench/src/`；统一样式变量见 `styles/tokens.css`；查询见 `cli/workbench/`。只维护 `cli/workbench/` 这一份展示查询和敏感键处理，不再保留旧 HTML 卡片或宿主桥接适配。

`package.json`、`package-lock.json`、前后端源码及配置入 Git。`node_modules`、`dist`、`.vite`、虚拟环境、`*.tsbuildinfo`、`workbench-logs` 不进入 Git 和基座无 Git 产物扫描；没有默认持久服务日志。Wiki 源码枚举沿用已配置的排除目录并在进入目录前剪枝。

验证按 [TESTING.md](TESTING.md) 只覆盖当前改动，临时测试执行后清理。不创建永久测试套件，不因 commit/push/构建/交付自动运行全量测试。

## 本地补验范围

本节是按实际变更选择的现场检查场景，不是一份每次必须全跑的清单，也不表示所有场景从未验证。已记录的历史范围见 [CHANGELOG](../CHANGELOG.md)；本次交付的未执行项和用户反馈单独记录，不能将后端隔离链路结果当成 React、Windows 或业务人验通过。

在本地环境需要准备或更新依赖时，从仓库根使用 `npm ci`；类型/构建确实受影响或此前未完成时，分别运行 `npm run check:types`、`npm run build`。通过既有启动入口打开页面，只用获准的 Task 或隔离夹具核对本次受影响面：

| 场景 | 具体操作与预期 |
|---|---|
| 步骤与角色 | 创建显式计划，开始两个可区分参与；在执行计划切换步骤并打开角色卡抽屉，确认范围/时间/证据互不覆盖，角色/步骤筛选计数与分页一致 |
| Fix 与集成 | 测试步骤等待 Fix，点击阻塞横幅中的 Work 链接打开“资料与 Work”抽屉并展开条目，接收结果和记录候选后刷新；父步骤不回退，未完成未来 Work 仍阻止整体结单 |
| 预检与失败 | 从“历史与证据”抽屉打开 Task 详情的“阻塞”标签并显式读取预检；缺候选显示 PENDING，变更产品/证据显示失效；请求失败保留旧读取时间并标历史，不继续显示当前可结单 |
| 历史与终态 | 无计划/缺参与显示空态或阶段活动，不伪造计划步骤；完成或取消后无当前执行者，旧 ACTIVE 接续标过期；返回/切换 Task 不泄漏前一上下文 |
| 视觉和键盘 | 1440/1024/715/480 CSS px、浅/深色；Tab、Enter/空格、Escape、抽屉/详情关闭后焦点、能力定义父子表搜索与展开；空态、错误态、长内容及窄屏无遮挡 |
| Wiki / 知识库 | 根据各自使用说明核对来源、检索/读取/采用口径、筛选、正文及失败/空态；人工浏览不增加 AI 使用记录 |

记录实际浏览器/平台、操作和失败项。视口模拟不等于物理触控设备；类型/构建/后端检查不替代这些交互，专业技术验收也不代签业务人验。发现具体问题按影响修复，不自动恢复历史全量测试。

## 子工作结果与中间/最终候选

“资料与 Work”抽屉中的“子工作与集成候选”复用原 Task 快照。点击阻塞/等待横幅中的关联 Work 链接会打开该抽屉并展开对应详情（收起时返回原按钮）；原步骤/角色时间线继续支持筛选。详情区分结果提交与协调接收，展示原步骤、当前接续、范围/路径/AC、依赖、工作区与隔离声明、精确结果事件和失败/重试历史。终态的未结束或缺失记录作为历史，不冒充正在运行。

候选区展示真实来源、接收集合、输出、冲突处置、证据和登记时仍未收敛的 Work。中间候选不代表整体可交付；最终适用性和所有 blocker 仍由只读结单预检核对。界面没有认领/批准/合并/结单按钮。相关操作及兼容界限见 [Work 结果契约](WORK_UNITS.md)。

这部分的语法/后端快照检查不能代替实际页面验证。有/无 Work、失败回收、关联链接展开与焦点返回、终态、窄屏、刷新失败与键盘操作按实际影响核对，结果和未执行项分别记录。

## 工作台外观与交互

顶栏提供“跟随系统／亮色／暗色”，默认跟随系统，浏览器偏好键为 `tp-spec.workbench.theme`。非法值或存储不可用时采用系统主题，存储失败不阻止当页手动切换。HTML 首次绘制前设置有效主题；系统模式实时响应系统变化，手动模式保留选择。所有语义颜色集中在 `styles/tokens.css`，Ant Design 从同一组 CSS 变量生成亮／暗及紧凑主题，各页面、抽屉与详情共用该主题。主题变化不触发业务数据读取，也不重置展开项或筛选状态。

桌面侧栏保留拖动、双击复位与方向键调整；宽度不大于 800px 时采用模态导航抽屉，选择目标后关闭并聚焦主内容，Escape／遮罩关闭返回导航按钮。断点收起不会将焦点留在隐藏区域。搜索浮层可从输入或结果上按 Escape 返回触发按钮。普通反馈 140ms、面板和侧栏约 200ms，拖动即时跟随；`prefers-reduced-motion` 关闭非必要动画和位移。

全局配置保留安装基座、Wiki/知识库入口、能力父子表与可展开的完整环境字段。项目总览优先展示 Runtime／版本摘要、任务计数筛选与任务列表，技术身份和来源信息置于下方详情。计数直接使用完整 `task_index`：在途为未退休 NEW／ACTIVE／BLOCKED，其他包含已完成、取消、退休和未知状态。不可用数据展示“—”，不计作零；原始统计及 summary 保留在“已记录状态统计”中。列表每页 10 条，筛选或搜索变化回到第一页，切项目重置；阶段和责任角色仅表示索引记录，窄屏收入任务列，不解释为当前执行者。

主题、侧栏、索引筛选与焦点在 2026-09-21 本地视觉批次中的实际检查范围见 [历史验证记录](../CHANGELOG.md#history-workbench-visual)。该记录包含通过、未重跑及待用户验证的范围，不是该批次未覆盖的知识库等页面的验收依据。

## 任务备注

项目任务列表在“状态”左侧显示“备注”列，预览备注。筛选后的任务先按有无备注分组，再按最近更新时间倒序，排序后分页。点击预览或“添加备注”可打开编辑窗口，支持保存、取消和清空后保存。备注按项目和 Task 身份保存，刷新与服务重启后可继续读取。多窗口更新发生冲突时保留当前输入，读取最新备注后再决定修改。

备注只写工作台附加数据，不写 Runtime、Task 工件、事件、状态、阶段、责任角色、最近更新时间或验收证据。任务数据及其他现有接口继续只读。GET /api/projects/{key}/tasks/{id}/note 读取备注，PUT 仅保存备注文本及其版本校验。保存错误不会显示为成功。
