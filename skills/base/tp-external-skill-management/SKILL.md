# 自定义 SKILL 管理

## 对象与操作前检查

先读 [外部 SKILL](../../../docs/EXTERNAL_SKILLS.md#存放与接入)中本次适用的路径、登记字段和错误规则，再运行 `tp-spec skill list --query external:local: --json`，从结果确定本次进程的用户根、来源包和可选配置。此目录独立于 Base 和业务项目，也不等同于宿主的 Skills/插件目录。

将用户请求解析为具体来源、包 ID 和动作；`external:local:<包目录>` 是对象身份，显示名不唯一。检查已有配置、包内容与引用、目标状态和本次授权，修改前保留必要原件或可恢复差异。未指定来源或同名冲突时先解决具体歧义，不自动从网络下载或挑同名包。

查询只读。管理操作通过宿主正常文件工具完成；当前 CLI 仅有 `skill list/read`，不得虚构 `skill install/add/remove` 等命令。

## 按请求选择动作

| 动作 | 修改范围与判定 |
|---|---|
| 导入 | 将已明确的来源包复制到所选用户根的 `external-skills/<包目录>/`，保留相对资源结构和来源原件。标准 `SKILL.md` 无需登记；不同入口名通过可选配置的 `entry` 定位。已有同 ID 时先比较差异，不静默覆盖。 |
| 更新 | 核对目标 ID、当前指纹、上游内容和本地自有修改，只替换用户已要求的范围；冲突需要具体决定。删除旧文件必须有本次更新依据，不能全目录清扫。 |
| 启用／停用 | 仅在该包的 `external-skills.yaml` 条目设置布尔 `enabled`；保留其他条目、已有字段与配置语义。停用保留包原件，不借阅读接口启用或采用。 |
| 关联 | 只修改该包 `applies_to` 中已存在的领域／正式角色 ID；关联用于目录发现与展示，不新增角色、执行次数、权限或固定步骤。未关联能力仍可发现。 |
| 移除 | 用户明确移除某 ID 后，核对真实绝对目标仍在所选 `external-skills` 下，且不是越界链接或未知归属；只移除该包及其登记条目，保留来源原件、其他包和共享配置。若用户仅要求停用，不删除包。 |

编辑共享 YAML 前重新读取并核对原内容未变；保留无关条目及字段，写入需原子替换或等价的安全文件操作。配置损坏、重复键或并发变化时保留原件，只停止受影响写入，不通过删配置绕开停用规则。目标是链接、路径越界或权限不明时停止对应动作并说明。

## 验证与反馈闭环

1. 修改后重新 `skill list`，按精确 ID 检查实际 `status/enabled/source_root/path`、关联和局部 `problems`，不使用旧摘要证明成功。
2. 导入、更新或启用后执行 `tp-spec skill read --id <ID> --json`；核对正文来源、入口、相对 Markdown 引用与实际 SHA-256。目录 `available` 不证明脚本可执行或依赖齐备，不运行包内脚本来凑验收。
3. 停用后列表应是 `disabled`，正常 CLI 读取应拒绝；移除且清除登记后 ID 应消失，读取应返回 `NOT_FOUND`。若保留登记但文件缺失，应如实报告 `missing`，不能冒充完整移除。
4. 已使用工作台或用户要求查看时，在相同用户根点击“重新读取”，检查节点、关联和正文。外部文件按请求实时读取，普通包变更不要求重启；更换用户根环境变量才重启相应进程。
5. 报告具体 ID、动作、前后状态、验证与保留/恢复情况。失败保留可恢复事实并说明责任和恢复条件；较新的用户改动出现后不盲目回滚覆盖。

## 隔离边界

不修改 Base 内置 Catalog/Manifest、业务项目 Binding/AGENTS、Runtime 或项目 Memory，不创建安装软链接。Base 维护技能本身是内置能力；被管理的外部方法保持用户资产，是否被某个业务任务采用由那个任务判断。管理授权不自动包含脚本执行、依赖安装、宿主注册、发布或生产操作。
