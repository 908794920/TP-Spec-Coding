# Python

与[共用标准](../coding-standards.md)一起使用。确认 Python 版本与项目采用的 PEP 8、formatter/linter 配置；项目已有约定优先，保持公开 API 兼容。

- 变量/函数通常用 snake_case、类用 CapWords；缩进、导入分组和换行跟随项目规则。PEP 8 的建议行宽不覆盖已有 formatter 配置。
- 简洁且清楚的推导式、迭代和标准库调用可以保留；多层条件、循环与副作用混杂时展开可读控制流。
- 仅捕获契约要求处理的异常；保留已明确的回退及异常传播，不为“健壮性”一概 catch Exception 或强制转换输入。
- 公共接口需要的使用契约可用 docstring 表达；实现注释说明原因与约束。没有项目要求时，不为简单私有函数补无信息的注释模板。
- 涉及文件、连接、锁或异步任务时核对资源所有权与实际生命周期。类型标注与返回值变化结合调用者决定。

例如简单的 `sorted(items)` 无需拆成多个 helper；容器类型与空输入处理取决于已确认契约。批准的兼容处理应明确原因和真实退出条件，不能借补注释改变行为。

来源核对于 2026-11-16。PEP 8 尊重项目一致性且不建议为风格破坏兼容；PEP 257 用于文档字符串约定，具体适用范围以项目为准。

- [PEP 8](https://peps.python.org/pep-0008/)
- [PEP 257](https://peps.python.org/pep-0257/)
