# Java

与[共用标准](../coding-standards.md)一起使用。先确认项目采用的手册版本、JDK、框架及 Checkstyle/P3C/formatter 配置，只引用本次适用条款。

- 遵循项目 Java 命名约定，让类、方法、变量表达业务含义；避免不明缩写和单位缺失。状态码的业务名称从已确认定义取得，不猜测枚举语义。
- 按项目格式安排括号、换行、导入和空行。复杂条件可提炼有业务含义的局部变量，避免只为少行数压缩控制流。
- 用 Javadoc 或已有文档说明对外接口必要契约；实现注释解释兼容、线程安全、顺序约束和非显然选择。
- 修改集合、相等判断、装箱、Stream、异常、资源或并发代码时核对真实类型与调用；资源关闭优先沿用适用的标准机制。已有业务异常与 fallback 要按契约处理。

例如 `process(int x, int y)` 无法解释操作意图时，可依据真实语义调整内部方法和参数名；已有公开 API、JavaBean 属性或映射字段的改名必须核对消费者。简单清楚的 Stream 不因风格被强制改循环；复杂 Stream 也不能用“函数式”作为难以维护的理由。

来源核对于 2026-11-16。阿里官方在线指南用于命名、格式、注释等主题参考；官方仓库标示黄山版，旧 GitBook 有过期提示。此次未成功读取黄山版 PDF 正文，不声明逐条复刻其最新条款；项目指定该版时再核对原文。Java 特有的前后缀、层次设计及限值不推广到其他语言。
