# 数据库设计与变更

## 适用范围
模型、Schema、SQL/Mapper、索引、Migration、事务、一致性、历史数据修复与数据库性能；按当前事项选用，不固定执行整张清单。

## 原有数据与授权原则
1. 先识别读/写、测试/生产和 DDL/DML 风险级别；生产写与 DDL 必须保持 human_owner 明确授权。
2. Migration 必须包含兼容窗口、回滚/恢复、数据一致性与大表/锁风险判断；不能只给 happy-path SQL。
3. 查询优化优先基于真实执行计划/索引/数据分布证据，而不是只看 SQL 文本猜性能。
4. 设计阶段可只读参与（effects=[]）；真正修改 schema/code 时声明 `repo_mutation`，必要时叠加数据库高风险授权。
5. Test Engineer 负责独立验证，Database Engineer 不自证最终 PASS。
6. SQL 按用途归属而不是按扩展名归属：随产品部署/迁移的 SQL 放目标仓库既有正式目录；一次性调查、回读和验证 SQL 放当前 Task `evidence/sql/`；临时生成物使用受控 Temp。
7. 修改/删除现有 SQL、Mapper、Schema 前检查真实调用、Migration 历史、兼容窗口和外部数据契约，优先复用或修改既有路径，不并行堆叠第二套实现。

## SQL / 执行计划
固定目标数据库及版本、调用入口、参数、结果语义、表/索引和可用数据分布；先确认查询正确性、NULL/重复/分页排序和边界，再比较计划、扫描行/索引选择及已获准的测量。EXPLAIN ANALYZE 等可能实际执行语句，不能因为名称含 EXPLAIN 就当作无副作用只读；缺环境/数据只给待验假设，不编造计划和性能提升。

## 迁移与回滚
明确旧→新 schema/数据版本、调用方发布顺序、兼容窗口、锁与大表风险、备份/恢复前提。按目标项目既有机制形成前置检查、执行、回读核对、失败恢复/补偿；只有需要时采用分步扩展/迁移/收缩。不可逆操作说明为什么不能 SQL 反向回滚、恢复所需材料和责任；不靠一份空 rollback 文件表示可恢复。

## 一致性与独立验证
核对真实事务边界、隔离级别、并发更新/唯一约束、重试幂等及跨系统部分失败；不默认新增分布式事务。记录执行环境、获准动作、实际结果、受影响范围及恢复证据；仅生成脚本记“未执行”，UI 人验不等于数据库已执行。将可复验输入交测试工程师，不自行完成父 Task。
