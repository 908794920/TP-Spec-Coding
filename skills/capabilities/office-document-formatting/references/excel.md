# Excel：按用途保留数据、计算与原生格式

## 选择格式与字段

先用用户要求、适用客户/招采/合同模板；局部编辑默认沿用仍有效的原件结构和同类样式。没有这些依据时，才采用本页的保守显示基线。Excel 不套用 Word 公文的字体字号、行字数或页面要求。内容角色确认统计口径和业务假设，格式能力不增补税率、汇率、工作日历、折扣、完成条件或必填列。

| 用途 | 按实际需要表达 | 计算与保留边界 |
| --- | --- | --- |
| 数据报表 | 来源、期间、单位、维度、指标及比较范围 | 区分流量、期末余额和比率；金额可加总，比率按对应分子/分母算，编号、版本和序号不求和；无需固定汇总页 |
| 项目排期 | 工作项、负责人、起止日期、依赖、里程碑、进展 | 日期为可计算值；自然日/工作日及包含首尾日期的口径来自需求；色块不冒充排程计算 |
| 报价 | 品项、单位、数量、单价、币种、金额、含税口径、范围/有效期 | 按已确认口径核数量乘单价、舍入及合计；不擅设税汇率、折扣或人天 |
| 测试用例 | 原流程的标识、前置、输入/步骤、预期、实际和结果 | 编号为文本时保留前导零；长步骤不截断；是否筛选、冻结、跨页重印表头由实际阅读/打印需要决定，不套财务分层 |
| 财务测算 | 已确认的输入、计算、输出、日期/期间及单位 | 用清晰公式表达余额滚动、金额或比率；不把余额逐期相加，不造假设；财务模型适用时可借鉴 FAST，不强制所有工作簿采用财务色码/分层 |

数字、日期、百分比、金额保存为相应类型，显示格式不代替类型转换。真正的标识使用文本；不要为美观将日期、货币或百分比转为字符串。单位、精度、正负号和舍入口径以业务/模板为准；空白、零、不适用和错误不能互相替换。公式保留公式及引用，不自动转为值，不用 `IFERROR(...,0)` 掩盖未定位的错误。

## 无模板的固定显示基线

使用唯一片段 [excel-styles.mjs](../examples/excel-styles.mjs)。它采用 `@oai/artifact-tool` 公开的 `Range.format` API，仅给调用方明确传入的新建正文/表头范围设置样式：中文宋体（字体名 `SimSun`）11pt、黑字，表头同字号加粗、浅灰 `#E7E6E6`。这是本方案设计默认，不是统一行业字号或强制标准。字体须在生成和目标环境实际可用；缺失时报告实际替代和影响，不打包系统字体、不静默换字体。

片段导出 `excelNumberFormats`，由内容语义明确选择后直接用于目标范围：文本标识 `identifier: "@"`、整数 `count: "0"`、金额示例 `amount: "#,##0.00"`、百分比 `percentage: "0.00%"`、日期 `date: "yyyy-mm-dd"`。金额格式自身不声称币种或含税口径；需要小数的数量、不同精度/日期样式沿用实际要求，不因示例格式限制输入。

调用示例仅说明原生绑定，不创建工作簿或推断业务：

```js
import { applyExcelStyles, excelNumberFormats } from "../examples/excel-styles.mjs";
applyExcelStyles(sheet.getRange("A4:F8"), sheet.getRange("A4:F4"));
sheet.getRange("A5:A8").setNumberFormat(excelNumberFormats.identifier);
sheet.getRange("E5:F8").setNumberFormat(excelNumberFormats.amount);
```

列宽、行高按本次真实内容和渲染调整，换行只用于需要的描述；不要统一列宽、缩小字号塞版或整表 autofit 改掉原布局。冻结、筛选、网格、打印方向/区域、分页、重复表头按用途和既有模板决定；片段不替用户设置这些行为。图表文字/坐标轴格式须另查工具的实际字体单位并绑定同一已选字体，单元格字体不会自动控制图表。客户模板或原件已选定后，记录文件/hash 与实际样式；新增同类内容复用相邻原生格式，不重新设计色板/字体，不重置整本工作簿。

## 新建与局部编辑

新建前明确读者、用途、目标引擎、输入、计算和输出；保持最简单的实际结构，不把一张业务表机械拆为多个 Sheet。本页用途矩阵不是固定列结构或五 Sheet 模板。

局部编辑先在副本捕获本次相关 Sheet、范围、数据类型/值、公式/引用、名称、表/图表、验证、条件格式、批注/备注、隐藏/保护、冻结、打印及计算设置的结构与真实显示基线。只改指定范围及直接受影响依赖；不改未授权 Sheet 顺序/名称、筛选、样式或对象。新增同类范围复用相邻格式，并按实际依赖扩展表、公式和图表范围；复制含内容的范围时核对值/公式，不能以复制格式为由覆盖原数据。

本 Codex 宿主按 **Spreadsheets** Skill 及 dependency loader 使用 `@oai/artifact-tool`：新建或先 `SpreadsheetFile.importXlsx` → 定点编辑 → 适用重算与检查 → `workbook.render` → `SpreadsheetFile.exportXlsx`。宿主对依赖、操作标记和输出的要求继续有效，Base 不硬编码本机路径，也不将宿主库变成所有平台的强制依赖。其他宿主或经证实且宿主允许的具体能力缺口，可复用已装工具；`openpyxl` 等读写库本身不是公式计算引擎。

宏、外链、签名、透视表、OLE/嵌入对象、旧 `.xls` 等先核实际字节和本次工具支持，再决定保留/原生编辑路径。常规 import/export 成功不证明这些对象保真；少见结构不等于输入非法。已知导出不支持的对象不盲目整本重存。局部不支持时说明受影响对象、可保留范围和恢复条件；转换、失去签名/编辑性或丢失内容的重大取舍交用户，不静默扁平化、丢弃或只改扩展名。

## 分层验证与重复处理

1. **结构/语义：** 对照目标及全书保留范围的值、数据类型、公式/引用、名称、对象和格式；检查公式复制的首/中/末位置与下一条扩展。独立核对已知输入、单位、期间、比率分母、舍入和适用合计，不自动给无语义数值加 SUM。扫描并定位 `#REF!`、`#DIV/0!`、`#VALUE!` 等实际错误，区分有意缺数标记。
2. **运行/重算：** 本次涉及公式、跨表引用、图表、条件格式等实际计算行为时，用副本改一个应影响结果的输入，确认相关结果真实更新，再恢复测试输入。记录实际计算引擎/版本、输入与输出，导出后按风险核缓存/计算链/外链等影响；公式文本、静态缓存和导出成功均不等于重算。遵守当前宿主对最终编辑后重算的要求；这不把无内容修改的每次重存都变为 Base 强制重算。
3. **真实视觉/打印：** 新建检查每个 Sheet，局部编辑检查变更和关联视图，并核全书未意外损失。实际渲染后查中文缺字、关键数字/单位/日期截断、`####`、换行、图表标签、宽高、分页及按用途需要的打印视图。屏幕范围 PNG 不证明打印分页；LibreOffice 渲染/重算不冒称 Excel/WPS 原生验证。若保存的文本标识/类型正确而某预览误显前导零，保留错误预览作诊断并改用已验证目标应用渲染，不修改业务标识迁就预览，不把错误预览报作视觉合格。
4. **重复处理：** 需要验证稳定性或存在已知漂移风险时，用副本按同一选择再次编辑/保存；比较实际涉及的目标值、类型、公式、引用、对象及格式，记录适用重算与保存后的真实差异。涉及缓存、计算链、外链、图表或条件格式时核相应副作用；不遗漏目标修改，不持续漂移，不以缓存值或 ZIP/hash 全等作为条件。

证据保留真实输入/输出 hash、操作范围、工具/版本与实际字体、各层结果及未验项；临时实验按项目既有规则清理，不建长期测试框架。没有目标应用、渲染器或重算能力时，继续独立可靠范围并列出未验证项、影响和恢复条件；生成/结构合格、重算、视觉检查和人工接受分别报告。
