# 原型与交互设计

> 改编说明（2026-09-20）：按 TP-Spec 的 Task/授权/证据边界重写 Impeccable 的 Operate/Animate/Adapt 方法，并有限采用 Taste 的 brief-first 思路；不是上游完整安装。准确文件、固定 commit、许可与取舍见 [第三方声明](../../../THIRD_PARTY_NOTICES.md#p1-视觉方法适配)。不加载上游引擎、Hook、付费服务、默认框架或审美硬规则。

## 归属与输入
产品经理负责设计方向与原型；开发工程师承接产品代码；测试工程师核验真实视觉/交互。角色是职责，不因此新建 Agent。先读当前 canonical Requirement/Task 的目标、用户、有效范围、AC、既有批准与目标设备；已有回答直接沿用，只为真实业务/体验/验收取舍补问。

用一段简述明确：新建还是保真改版、页面用途/用户、沿用的视觉系统与真实约束。操作型产品优先状态清晰、熟悉的控件与可操作密度；品牌/展示页可按明确 brief 调整。不因想“更好看”改字段、动作、权限或业务含义，不强制 React、Figma、特定字体/配色或新增组件库。

## 三类清单：按规模写入既有工件
| 清单 | 最小内容 | 事实依据 |
|---|---|---|
| 页面/状态 | route/入口、用户/权限、正常/空/加载/失败/完成状态、可达路径、对应 AC | 新功能来自确认需求；既有改版核对真实入口和动态 DOM |
| 字段/动作 | 标签、值/类型/必填、可见/可编辑条件、默认值来源、动作/返回/重复操作、提交参数 | 真实代码、公共组件及获准业务规则；未知不自动填入 |
| 请求/加载 | 请求/触发、参数、作用区域、开始/结束、成功/失败/重试/取消、重复与离开清理 | 真实调用及接口；无后端原型明确标为模拟 |

小范围可用一张紧凑表，不要求三份文件；复杂任务在当前设计工件分节维护，入口只引用。不要仅看静态截图猜动态控件，不能复制 W08 的字段、数量、流程轮次为公共规则。

## 视觉来源与组件落实
分开记录：原视觉规范/获准参考 → 真实组件/样式及调用映射 → 本项目适配 → 用户明确批准的例外。布局、主题、token、按钮、表单、浮层、反馈先复用已有能力；共享组件必须实际 import/调用并在浏览器看到结果，复制资源、同名样式或只写映射表都不是落实。

已有项目保持品牌/控件语义，设计参考不能冒充官方实现。新增依赖只有现有栈无法合理完成且收益覆盖成本时才考虑；重大依赖/付费/外发需授权。保留一处有效设计，不自动增加 PRODUCT.md/DESIGN.md 与 Task 并列维护业务事实。

## 可操作原型
1. 选代表性的真实路径，按三类清单连通入口、填写/选择、校验、提交/取消及反馈，不能只做静态画面。
2. 加载只覆盖实际受影响区域；确认重复点击策略，失败保留可恢复输入并提供重试。错误原因未知不能编造业务拒绝；取消/返回/离开后不让迟到结果覆盖新页面。
3. 临时 Mock、受控时延、示例值、评审壳和自动填写独立放获准隔离原型目录，明确“模拟”；不接真实生产、不创建真实身份、不把评审工具混入产品。原型只证明设计方法，不证明业务后端或权限正确。
4. 按当前 brief 的视口和实际内容选择断点，保证窄屏必要字段/动作可达、长文本可读、浮层不裁剪、键盘/触控路径可用。不能以缩小字体或隐藏核心功能假装响应式。原系统已有密度/导航无需为参考重造。
5. 存在动效或异步交互时读 [交互与动效](references/interaction-and-motion.md)；没有动效需求不添加装饰动画。反馈必须独立于动画结束存在。

## 代表验证与评审
主题/公共组件和代表页面按实际规模组织评审，局部返修只查受影响点，不固定三轮审批。先按三类清单跑一轮成组的真实浏览器检查（目标宽/窄视口、正常/加载/失败/恢复及必要动效），修复确定问题后做定向确认；不要开放式无限抛光或改变已批准参考。

真实点击/输入/返回/重复操作、Console/Network 与必要截图/动效过程作为证据；静态 grep、DOM 字符串、图片生成和编译不能代替该结论。记录真实浏览器、视口/输入方式、版本、预期/实际、未知与未执行。模拟移动视口不是微信/OAuth/相机/真机/生产权限通过。正式 Evidence/Visual Manifest 复用 [Visual QA](../testing-strategy/references/visual-qa.md)，不另建视觉报告系统。

## 交接与完成边界
交付当前批准的范围/版本、三类清单、组件调用位置、适配/例外、模拟设施边界、浏览器证据及未解决项；复用 Task/设计工件，不额外四套总结。设计批准、前端实现、真实业务/权限验收分别表达，不能互相代替。开发按 [实现过程控制](../implementation-control/SKILL.md) 承接，不携带 Mock/时延/自动填写/评审壳；测试按实际 AC 独立核验。需要权限或环境的动作保持待验，不因原型通过自行部署或发布。
