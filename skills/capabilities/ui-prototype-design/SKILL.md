# 原型与交互设计

> 改编说明（2026-09-20）：按 TP-Spec 的 Task/授权/证据边界重写 Impeccable 的 Operate/Animate/Adapt 方法，并有限采用 Taste 的 brief-first 思路；不是上游完整安装。准确文件、固定 commit、许可与取舍见 [第三方声明](../../../THIRD_PARTY_NOTICES.md#p1-视觉方法适配)。不加载上游引擎、Hook、付费服务、默认框架或审美硬规则。

## 归属与输入
产品经理负责设计方向与原型；开发工程师承接产品代码；测试工程师核验真实视觉/交互。角色是职责，不因此新建 Agent。先读当前 canonical Requirement/Task 的目标、用户、有效范围、AC、既有批准与目标设备；已有回答和批准直接沿用，只有尚未解决的实质业务/体验/品牌/验收取舍才交 human_owner，不因读取本 Skill 追加确认。

用一段简述明确：页面用途/用户、本次改动范围、可复用的视觉系统与真实约束。操作型产品优先状态清晰、熟悉的控件与可操作密度；品牌/展示页可按明确 brief 调整。不因想“更好看”改字段、动作、权限或业务含义，不强制 React、Figma、特定字体/配色或新增组件库。

## 设计系统来源与适用条件
基于当前范围、已有批准和实际可用资产选择路径，先判断是否只是局部返修；以下是条件性工作方法，不新增 Runtime phase、Task 或固定审批。

| 路径 | 适用输入 | 本次处理 |
|---|---|---|
| 新建且无系统 | 新产品或整体视觉重做，且没有已批准且可实际复用的系统 | 先选一条高频代表路径，形成仅覆盖其必需视觉方向、共用元素和关键状态的最小基线；代码化、实际调用并验证后再扩展，不预建完整组件库 |
| 已有系统复用 | 已有系统或成熟代码组件，真实资产可定位且适用于本次范围 | 引用规范、变量、组件及实际调用位置，只补本次缺失状态、适配和明确批准的例外，不重造主题或组件库 |
| 局部返修 | 局部按钮、样式、交互返修或低影响页面调整 | 沿用现有约定，只更新受影响控件、页面与证据；没有独立基线文件也不要求补全系统或重做完整产品设计 |

最小基线写入当前唯一有效设计工件，已有内容直接引用；只明确代表路径必需的公共视觉、交互约定和实现关系，不增加平行的业务事实。

## 三类清单：按规模写入既有工件
| 清单 | 最小内容 | 事实依据 |
|---|---|---|
| 页面/状态 | route/入口、用户/权限、正常/空/加载/失败/完成状态、可达路径、对应 AC | 新功能来自确认需求；既有改版核对真实入口和动态 DOM |
| 字段/动作 | 标签、值/类型/必填、可见/可编辑条件、默认值来源、动作/返回/重复操作、提交参数 | 真实代码、公共组件及获准业务规则；未知不自动填入 |
| 请求/加载 | 请求/触发、参数、作用区域、开始/结束、成功/失败/重试/取消、重复与离开清理 | 真实调用及接口；无后端原型明确标为模拟 |

小范围可用一张紧凑表，不要求三份文件；复杂任务在当前设计工件分节维护，入口只引用。不要仅看静态截图猜动态控件，不能复制 W08 的字段、数量、流程轮次为公共规则。

## 最小设计基线
新建基线或现有基线缺少本次必要约定时，按需读取 [基线产物与消费说明](references/design-baseline.md)。七类信息按当前路径裁剪，已有内容直接引用，不要求补全七项或七份文件。三类清单继续记录页面、字段/动作、请求/加载的业务事实；基线通过清单条目引用补充公共视觉、交互约定及实现消费关系，不重复维护字段、权限或接口规则。

## 视觉来源与组件落实
分开记录：原视觉规范/获准参考 → 真实组件/样式及调用映射 → 本项目适配 → 用户明确批准的例外。布局、主题、token、按钮、表单、浮层、反馈先复用已有能力；共享元素必须按当前项目栈实际调用（组件、模块、公共函数或模板），并在浏览器看到结果，复制资源、同名样式或只写映射表都不是落实。

外部图片、竞品和内置主题只作有来源及明确批准范围的参考；只有参考图不等于已有可复用系统，也不代表客户品牌、素材许可或执行授权。整页示例用于评审布局和交互，不自动成为生产页面模板。

已有项目保持品牌/控件语义，设计参考不能冒充官方实现。新增依赖只有现有栈无法合理完成且收益覆盖成本时才考虑；重大依赖/付费/外发需授权。保留一处有效设计，不自动增加 PRODUCT.md/DESIGN.md 与 Task 并列维护业务事实。

## 可操作原型
1. 按所选路径沿用或补齐最小基线，由开发工程师用当前项目栈实现并实际调用所需共用元素，再按三类清单连通一条代表路径的入口、填写/选择、校验、提交/取消及反馈，不能只做静态画面。局部返修只调整受影响交互，不重做完整原型。
2. 加载只覆盖实际受影响区域；确认重复点击策略，失败保留可恢复输入并提供重试。错误原因未知不能编造业务拒绝；取消/返回/离开后不让迟到结果覆盖新页面。
3. 临时 Mock、受控时延、示例值、评审壳和自动填写独立放获准隔离原型目录，明确“模拟”；不接真实生产、不创建真实身份、不把评审工具混入产品。原型只证明设计方法，不证明业务后端或权限正确。
4. 按当前 brief 的视口和实际内容选择断点，保证窄屏必要字段/动作可达、长文本可读、浮层不裁剪、键盘/触控路径可用。不能以缩小字体或隐藏核心功能假装响应式。原系统已有密度/导航无需为参考重造。
5. 存在动效或异步交互时读 [交互与动效](references/interaction-and-motion.md)；没有动效需求不添加装饰动画。反馈必须独立于动画结束存在。

## 代表验证与评审
新建或本次调整的公共模式先随代表路径验证，再扩展到依赖它的其他页面；已有且未受本次影响的有效基线与证据直接沿用。扩展页面出现真实新模式时才增补基线并定向复验，不为未来可能需要的组件提前扩建。

主题/公共组件和代表页面按实际规模组织评审，局部返修只查受影响点，不固定三轮审批。按当前 AC 和受影响的三类清单跑一轮成组的真实浏览器检查（目标宽/窄视口、正常/加载/失败/恢复及必要动效），修复确定问题后做定向确认；不要开放式无限抛光或改变已批准参考。

真实点击/输入/返回/重复操作、Console/Network 与必要截图/动效过程作为证据；静态 grep、DOM 字符串、图片生成和编译不能代替该结论。记录真实浏览器、视口/输入方式、版本、预期/实际、未知与未执行。模拟移动视口不是微信/OAuth/相机/真机/生产权限通过。正式 Evidence/Visual Manifest 复用 [Visual QA](../testing-strategy/references/visual-qa.md)，不另建视觉报告系统。

浏览器或环境不可用时，如实标记未验证，不声称基线已通过，也不批量复制尚未验证的公共模式。仍可交付可供试用的源码，并继续不依赖该验证结果的已获准工作；不把尚未发生的用户体验前置为源码交付条件。

## 交接与完成边界
交付当前批准的范围/版本、受影响三类清单，以及同一有效设计工件中的基线、组件约定与实现/预览位置、页面到组件的真实调用映射、适配/批准例外。开发先读取本次需要的变量和组件约定，再沿映射用当前项目栈实际调用；整页示例只用于布局和交互评审，不自动成为生产模板或复用证明。

同时交代代表路径的验证状态及对应版本、浏览器证据、模拟设施边界、真实能力待验范围和未解决项；尚未实现的位置、未验证的结果如实标明，不把计划路径写成现有资产。仅在新建或补缺时读取 [基线产物与消费说明](references/design-baseline.md)；局部返修只交接受影响内容，没有独立基线文件也不补建整套系统。

复用 Task/设计工件，不额外四套总结。设计批准、前端实现、真实业务/权限验收分别表达，不能互相代替。开发按 [实现过程控制](../implementation-control/SKILL.md) 承接，不携带 Mock/时延/自动填写/评审壳；测试按实际 AC 独立核验。需要权限或环境的动作保持待验，不因原型通过自行部署或发布。
