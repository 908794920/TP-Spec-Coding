# 最小设计基线：产物与消费

## 何时读取与写在哪里
仅在新建基线或现有基线缺少本次必要约定时读取；先按 [设计系统来源与适用条件](../SKILL.md#设计系统来源与适用条件) 选择路径。下面是可裁剪的信息类别，不是每个 Task 的必填表或七份新工件。已有约定直接引用；局部返修只补受影响内容，不因缺少独立基线文件重做设计。

信息写入当前唯一有效设计工件，规模小可合并成一张表。页面、字段/动作、请求/加载仍以 [三类清单](../SKILL.md#三类清单按规模写入既有工件) 为业务事实来源；基线引用对应条目，只补公共视觉、交互约定及消费关系，不复制字段、权限、接口或业务规则。

## 七类最小信息
| 类别 | 本次需要说明的内容 | 来源与消费位置 |
|---|---|---|
| 视觉来源与方向 | 现有规范、获准参考或新方向；目标用户/设备；事实、建议、已批准决定和未决取舍分开 | 指向当前设计章节及已有批准；产品据此定方向，开发沿用批准范围，外部图片不等于真实资产或客户品牌 |
| 语义设计变量 | 当前需要的主/辅/中性色及文字、背景、边框、反馈用途；文字层级、间距、圆角和状态映射 | 指向实际变量定义及名称/用途，供组件消费；已有值直接引用，不为齐全预建未来变量 |
| 图标与素材 | 实际来源、名称、尺寸/描边或填充规则、已有许可记录及替换边界 | 指向现有素材或图标入口；未知许可不推断，替换不能自行改变动作语义 |
| 共用组件约定 | 名称/用途、真实签名、参数类型/默认值与输出、必要尺寸/变体、成组状态、点击/键盘语义、错误/禁用反馈、窄屏行为与变量/资产消费 | 从目录定位具体规格、真实文件/符号、调用示例和可操作预览；开发据此调用，评审/测试查看适用的正常及关键异常状态 |
| 页面框架与交互模式 | 本路径需要的导航、固定/滚动区、安全区、浮层层级、搜索/筛选及加载/空态/失败/成功反馈 | 指向实际布局/公共实现及受影响页面，供开发落实、测试核对遮挡和动作可达性 |
| 页面到组件映射 | 页面/状态清单条目 → 页面实际文件/调用符号 → 共用实现；代表组合页面、项目适配与批准例外 | 可定位当前栈的实际调用关系；代表组合展示布局及状态配合，复制 CSS、同名 class 或只有组件表不能证明复用 |
| 可操作预览与证据 | 具体组件与代表路径的预览入口、当前范围/版本与源码快照、浏览器/视口/输入方式、预期与实际点击结果、模拟及未验证范围 | 入口可找到既有 Evidence 和待验项；历史结果绑定适用版本，截图或构建结果不替代交互验证，不额外建设报告平台 |

只填写当前代表路径或受影响点实际需要的信息；没有使用图标等类别时不为齐表造资产。已有规范、组件和预览直接引用，不重复抄录。没有独立组件预览时可在代表页面核验，不要求 React、Figma、Storybook、JSON 契约、特定目录或单独组件包。

尚未实现的资产标明“待实现”，已存在但未核验的调用或预览标明“未验证”，不能用计划路径冒充现有实现。只有参考图时，沿主 Skill 选择适用路径，不据图推断代码复用；整页示例只供布局/交互评审，不自动成为生产页面模板。

## 新建或系统性补缺的交付粒度

设计系统覆盖本次实际使用的共用组件。小系统可在同一有效工件用目录、组件条目与成组状态表组织；已有平台直接引用相应页面，不另建一份契约。目录项必须到达具体组件，不能仅链接一张包含所有示例的大卡片。

| 一个组件条目 | 最小可核对表达 |
|---|---|
| 来源与使用 | 名称、适用场景、真实文件/符号；原系统引用、项目适配与批准例外分开 |
| 调用契约 | 当前真实签名、各参数类型/默认值、输出或事件、必要短调用；不存在的参数不补造 |
| 变体与状态 | 实际支持的尺寸/样式；本路径需要的状态按组件成组，区分已实现、待实现、未验证和不适用；不适用有理由，状态不产生业务准入规则 |
| 预览与消费 | 可操作入口/锚点、token/资产的定义及消费位置、实际页面文件/调用符号；视觉示例与真实业务调用分别指明 |
| 验证与版本 | 当前版本/源码快照、受影响清单条目及必要 AC 引用、真实证据入口与待验范围；代码变化后核对旧结果适用性 |

必要状态不要求所有组件拥有同一矩阵。例如静态图标的提交失败不适用；保存动作的错误通常由字段/反馈组件显示，应指向该组合而非臆造按钮 API。源码中的尺寸或 token 例外保留实际依据；不为消除所有字面值重写业务布局。资产目录按本次真实使用的图标/素材列名称、来源、语义和预览，不以数量扩建；名称过滤只在查找有实际需要时添加。

先落实这些条目与一条代表组合，按主 Skill 做代表验证后再扩展页面。组合可以是现有购买/编辑页面，无需制作通用 Dashboard 或模板图库。范围小不等于可以省略真实入参和调用关系；局部返修只补受影响条目，格式、组件数量和平台功能都不作为独立验收门槛。可直接参考 [小系统组件消费示例](component-consumption-example.md)。

## 下游 AI 的消费次序与唯一来源

1. 从有效设计入口核对当前范围、版本、预览及验证边界，沿三类清单读取所需页面/字段/请求事实。
2. 按组件目录读取本页需要的真实签名、参数默认值、变体状态及 token/资产消费；再核对源码和现有页面调用点，不能只读映射摘要。
3. 沿代表组合实际调用现有组件，添加本页获准差异；发现真实新模式再补相应约定并定向验证，不复制截图重新实现同一组件。

一处 effective 设计工件持有当前消费约定；README、页面目录和任务入口只链接或由同一来源生成，不各自维护参数/状态。真实源码决定当前 API，设计工件说明消费和适配，三类清单持有业务事实，Evidence 保存对应版本的观察；出现冲突先核对并更新当前工件，不能静默选取较方便的一份。

## 交接与验证消费
交接继续使用主 Skill 的 [交接与完成边界](../SKILL.md#交接与完成边界)：开发沿当前基线、变量/组件约定和页面映射实现，产品核对批准方向与业务含义，测试按当前 AC 核验受影响状态及调用。设计批准、原型模拟、产品代码和真实业务验收分别表达；现有授权不因新增基线说明而扩大。

预览、点击结果、真实组件调用及模拟边界使用既有 [Visual QA](../../testing-strategy/references/visual-qa.md) 留证。浏览器/环境不可用时按主 Skill 如实待验，不签通过、不批量扩展未验证公共模式，仍可交付试用源码和继续不依赖该结果的获准工作。
