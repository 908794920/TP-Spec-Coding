# 最小设计基线：产物与消费

## 何时读取与写在哪里
仅在新建基线或现有基线缺少本次必要约定时读取；先按 [设计系统来源与适用条件](../SKILL.md#设计系统来源与适用条件) 选择路径。下面是可裁剪的信息类别，不是每个 Task 的必填表或七份新工件。已有约定直接引用；局部返修只补受影响内容，不因缺少独立基线文件重做设计。

信息写入当前唯一有效设计工件，规模小可合并成一张表。页面、字段/动作、请求/加载仍以 [三类清单](../SKILL.md#三类清单按规模写入既有工件) 为业务事实来源；基线引用对应条目，只补公共视觉、交互约定及消费关系，不复制字段、权限、接口或业务规则。

## 七类最小信息
| 类别 | 本次需要说明的内容 | 来源与消费位置 |
|---|---|---|
| 视觉来源与方向 | 现有规范、获准参考或新方向；目标用户/设备；事实、建议、已批准决定和未决取舍分开 | 指向当前设计章节及已有批准；产品据此定方向，开发沿用批准范围，外部图片不等于真实资产或客户品牌 |
| 语义设计变量 | 当前需要的主/辅/中性色及文字、背景、边框、反馈用途；文字层级、间距、圆角和状态映射 | 指向实际变量定义及名称/用途，供组件消费；已有值直接引用，不为齐全预建未来变量 |
| 图标与素材 | 实际来源、名称、尺寸/描边或填充规则、已有许可记录及替换边界 | 指向现有素材或图标入口；未知许可不推断，替换不能自行改变动作语义 |
| 共用组件约定 | 使用场景、必要尺寸/变体/状态、输入输出、点击/键盘语义、错误/禁用反馈、窄屏行为与变量引用 | 指向真实实现和可操作预览，开发据此调用，评审/测试查看适用的正常及关键异常状态 |
| 页面框架与交互模式 | 本路径需要的导航、固定/滚动区、安全区、浮层层级、搜索/筛选及加载/空态/失败/成功反馈 | 指向实际布局/公共实现及受影响页面，供开发落实、测试核对遮挡和动作可达性 |
| 页面到组件映射 | 页面/状态清单条目 → 页面实际调用点 → 共用实现；项目适配与批准例外 | 标明模块/函数/组件/模板等当前栈的实际调用关系；复制 CSS、同名 class 或只有组件表不能证明复用 |
| 可操作预览与证据 | 组件关键状态或代表路径的预览入口、对应版本、浏览器/视口/输入方式、预期与实际点击结果、模拟及未验证范围 | 引用当前预览和既有 Evidence；截图或构建结果不替代交互验证，不额外建设报告平台 |

只填写当前代表路径或受影响点实际需要的信息；没有使用图标等类别时不为齐表造资产。已有规范、组件和预览直接引用，不重复抄录。没有独立组件预览时可在代表页面核验，不要求 React、Figma、Storybook、JSON 契约、特定目录或单独组件包。

尚未实现的资产标明“待实现”，已存在但未核验的调用或预览标明“未验证”，不能用计划路径冒充现有实现。只有参考图时，沿主 Skill 选择适用路径，不据图推断代码复用；整页示例只供布局/交互评审，不自动成为生产页面模板。

## 紧凑示例：异步保存按钮
以下仅说明如何表达消费关系：假设当前已批准的保存动作在处理中不接受再次提交。**名称、路径和状态是示例，不是本仓现有资产、固定目录或其他任务的公共义务；示例没有执行，不代表验证通过。**

| 约定 | 示例表达 |
|---|---|
| 业务依据 | 引用当前三类清单中的“保存”动作及请求条目；字段、权限、参数和成功含义仍以原条目为准，不在组件约定复制一份 |
| 实现与变量 | 假设 `ui/common/save-control.js` 的 `bindSaveControl` 绑定原生 `button`；使用 `ui/theme.css` 中本次需要的 `--action-bg`、`--feedback-error` 等语义变量 |
| 消费映射 | 假设编辑页入口 `ui/pages/editor.js` 的 `mountEditor` 实际调用 `bindSaveControl`；同时核对调用位置和运行结果，不能只看到同名样式就写“已复用” |
| 输入输出与激活 | 输入为目标按钮、当前保存回调及可用状态；输出为按原动作约定调用回调并呈现反馈。沿用原生按钮的鼠标/触摸及 Enter/Space 激活，不再叠加重复键盘触发；这里采用的处理中不重复提交策略只适用于上述假设 |
| 必要状态 | 默认/焦点、不可用、处理中、成功、失败与可达重试；焦点可见，错误有文字说明，失败保留可恢复输入。返回/取消及迟到结果仍遵循对应请求条目，不凭示例增加业务动作 |
| 窄屏与预览 | 长标签仍可读、按钮不被固定区遮挡，不隐藏必要动作。可在获准隔离原型的 `preview/editor.html` 展示关键状态，也可沿用现有代表页面；不为此新建预览平台 |
| 验证与边界 | 记录实际版本、浏览器/视口/输入方式、点击/键盘/重复操作及失败恢复结果，并定位既有证据。使用 Mock 时明确“模拟”；没有执行就记录“未验证”，不据原型推断真实保存、权限或后端通过 |

示例中的公共函数可替换为项目已有组件、模块或模板调用；只要真实消费关系可定位，不为满足某个 `import` 字样更换技术栈。

## 交接与验证消费
交接继续使用主 Skill 的 [交接与完成边界](../SKILL.md#交接与完成边界)：开发沿当前基线、变量/组件约定和页面映射实现，产品核对批准方向与业务含义，测试按当前 AC 核验受影响状态及调用。设计批准、原型模拟、产品代码和真实业务验收分别表达；现有授权不因新增基线说明而扩大。

预览、点击结果、真实组件调用及模拟边界使用既有 [Visual QA](../../testing-strategy/references/visual-qa.md) 留证。浏览器/环境不可用时按主 Skill 如实待验，不签通过、不批量扩展未验证公共模式，仍可交付试用源码和继续不依赖该结果的获准工作。
