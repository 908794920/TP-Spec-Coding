# 测试价值判定参考

每个 durable test 在保留前都应能回答：**“如果生产代码发生哪一种现实错误，这个测试会失败？”**

## 应优先保留
- 新业务规则和已修复缺陷的回归测试；
- 接口、事务、权限、数据兼容和关键边界测试；
- 稳定、可重复执行的组件/集成/端到端测试；
- 已有测试中最小扩展即可覆盖的新场景。

## 低价值反模式
- 不为静态常量本身写测试；
- 不检查“被删除的符号仍然不存在”；
- 不测试 Mock 自身；
- 不为了测试向生产代码增加 test-only helper；
- 已有行为测试覆盖时优先扩展/复用，不新建平行脚本；
- 源码 grep/DOM 字符串断言只能保护结构契约，不能冒充行为/视觉验证。

## 临时诊断测试
只用于定位一次性问题的脚本、Mock、截图工具和中间结果使用 TP-Spec 受控 Temp；问题解决后清理，不为了“已经写了”转成永久测试。
