# 测试价值判定参考

TP-Spec-Coding 自身源码使用 [本仓验证策略](../../../../docs/TESTING.md)。可复用交互脚本按 [Visual QA](visual-qa.md) 保存在对应项目 `.tp-spec/memory/`，是明确保留的长期资产，包含本仓自身；其他测试的留存仍按目标仓库规则，不能据此重建历史基座套件。

每个获准的 durable test 在保留前都应能回答：**“如果生产代码发生哪一种现实错误，这个测试会失败？”**

## 应优先保留
- 新业务规则和已修复缺陷的回归测试；
- 接口、事务、权限、数据兼容和关键边界测试；
- 稳定、可重复执行的组件/集成/端到端测试；
- 已有测试中最小扩展即可覆盖的新场景。

## 低价值反模式
- 不为静态常量本身写测试；
- 不检查“被删除的符号仍然不存在”；
- 不测试 Mock 自身；
- 不为了测试向生产代码增加 test-only helper；
- 已有行为测试覆盖时优先扩展/复用，不新建平行脚本；
- 源码 grep/DOM 字符串断言只能保护结构契约，不能冒充行为/视觉验证。

## 临时诊断测试
只用于定位一次性问题的脚本、Mock、截图工具和中间结果使用 TP-Spec 受控 Temp；问题解决后清理，不为了“已经写了”转成永久测试。

## 属性与变形测试

单个预期难以穷举、且当前 AC 或已核实契约提供稳定关系时，选择能暴露具体现实错误的一条关系。属性测试对有效输入断言同一不变量，变形测试比较输入变换前后的输出关系。例如分组统计已确认与顺序无关，可重排含重复组的数据并比较各组计数，同时保留有明确结果的小样本。若契约规定同键最后一行覆盖，直接验证该行为。

优先复用现有参数化或成对用例。确需扩大输入域且项目已有生成器时，直接构造满足前提的输入；保留可重放的反例、变换与差异。预期不由被测算法计算，契约不支持某条关系时改用有依据的具体用例。关系成立只覆盖本次输入和断言，不能代替关键的确定结果检查。方法出处见 [Hypothesis 官方教程](https://hypothesis.readthedocs.io/en/latest/tutorial/introduction.html)、[反例重放](https://hypothesis.readthedocs.io/en/latest/tutorial/replaying-failures.html) 与 [变形测试原始报告](https://www.cse.ust.hk/faculty/scc/publ/CS98-01-metamorphictesting.pdf)。

## 消融对照
固定代表性输入、模型、参考和可控参数，以当前规则为基线，在隔离副本每轮仅改一个因素。预先定义成功行为、关键回归及返工指标；随机波动明显时做必要复跑。保留权限、数据保护和证据真实性等硬约束。报告实际对照和覆盖范围，小样本未见变化仅是本次观察。
