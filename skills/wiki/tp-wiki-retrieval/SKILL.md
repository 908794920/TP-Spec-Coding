# Wiki 检索与读取

## 选择与范围

Wiki 用于缩小源码调查范围，不覆盖当前源码事实。位置已知或现有上下文足够时可直接核对源码；已有内容优先复用，不按角色或阶段重复搜索。

通过 Content Systems Resolver 使用当前工作区已登记的 Wiki；默认保持当前项目/repo scope，跨项目检索须有明确范围。文档 ID 使用搜索或 `wiki inventory` 返回值，不从文件夹名或 Runtime 项目 ID 拼接。

## 按需执行

按[统一检索与使用记录](../../../docs/WIKI_USAGE.md#ai-使用入口)使用 `tp-spec wiki search` / `wiki read`。已有准确文档 ID 直接读取；默认短预览不足时按实际返回的行号、续读标志或显式全文选项扩大范围，不预载整个 Wiki。

- 已知 Task/Role 可随调用传入；未知保持未关联，不为遥测另建 Task。一次逻辑重试复用 request-id，不同输入不用同一回执。
- 搜索命中、读取和实际采用是不同事实；只有实际使用才随已有 Task 操作登记 `context_usage`，保留准确 Wiki ID 和可用回执。
- 页面浏览、维护、测试和诊断不当作研发采用；测试/诊断使用正式无遥测选项。
- 索引缺失、过期或不可读时如实报告，必要时回到源码；不为了查询或计数自动重建索引、扩大到全局或机械重试。索引维护只在相应请求覆盖时执行，重建不清空使用日志。

## 输出

给出命中的文档及版本、相关片段、已核验源码和剩余未知；没有结果与读取失败分开。不要把未维护的 Wiki 当作当前源码结论，也不把无日志解释为从未使用。
